## 프로젝트 소개

BRIFO는 사용자가 투자 회사의 CEO가 되어 AI 사원에게 종목 분석을 맡기고, 보고서를 바탕으로 투자 방향을 결정하는 서비스입니다. 실제 매매 대신 결정과 회고를 반복하며 투자 판단을 연습하도록 만들었습니다.

개발 기간은 9주였습니다. API 명세가 자주 바뀌어 타입을 손으로 맞추거나 서버 DTO를 화면에서 직접 사용하면 수정할 범위가 커지는 상황이었습니다.

## 주요 구현

프론트엔드 3명 중 리드를 맡아 공통 API 연동 규칙을 정하고 팀원들과 40개 API 경로에 적용했습니다. Orval 설정과 API 요청, 인증 갱신, 에러 처리를 위한 공통 코드를 처음 작성했습니다.

Orval은 요청 함수와 DTO 타입, Zod 스키마만 생성하도록 했습니다. Query hook은 도메인별로 직접 작성해 Query Key와 캐시 정책을 관리했습니다. 생성 파일 수정 금지와 hook 작성 순서는 사용 가이드로 남겼습니다.

폼이 적어 도입하지 않기로 했던 Zod를 서버 응답 검증용으로 다시 제안해 도입했습니다. `queryFn` 안에서 응답을 검증하고 Mapper에서 화면 모델로 변환해 TanStack Query 캐시에 저장하도록 구성했습니다.

사원 목록과 상세 화면, 결정 일기, 마이페이지의 화면 구현과 API 연동을 맡았습니다. 결정 일기 공유 이미지와 카카오 공유도 구현했습니다. 공통 UI는 설계 초안과 검토 체크리스트를 만들고 팀원들과 나눠 구현했으며 저는 Modal, NavigationBar, BottomSheet 등을 맡았습니다.

Husky와 GitHub Actions로 커밋 전 코드 검사와 CI, 생성 코드 비교 검사를 구성했습니다. Swagger를 점검해 화면에 필요한 누락 필드와 실패 응답 문서화도 백엔드에 요청했습니다.

## 문제 해결

### 스키마 이름 충돌로 발생한 타입 오류 해결

문제 정의(Problem): 사원 목록 API에서 Orval이 생성한 타입이 실제 응답과 달랐습니다.

접근 과정(Process): 생성 타입과 Kotlin 응답 DTO를 추적해 중첩 클래스의 `Item` 이름이 OpenAPI 스키마에서 충돌하는 원인을 찾았습니다. 같은 구조를 쓰는 다른 목록 응답도 영향 범위에 포함해 백엔드에 전달했습니다.

해결(Solution): 백엔드에서 `GetAgentsResponse.Item`을 `AgentItem`으로 바꾸는 등 중첩 `Item` 13개를 고유한 이름으로 수정했습니다.

결과(Result): 12개 도메인의 응답 DTO 21개에 수정이 반영됐고 같은 원인으로 발생하던 타입 불일치를 함께 해결했습니다.

### 배포 환경의 9시간 날짜 오차 수정

문제 정의(Problem): 배포 환경에서 출석 시각이 실제 한국 시간과 9시간 어긋나 표시됐습니다.

접근 과정(Process): JPA Auditing이 KST Clock에 연결되지 않은 상태를 찾고 서버 시간 설정을 점검하도록 전달했습니다. AP 내역의 `createdAt` 등 날짜 응답도 확인해 KST `LocalDateTime`과 `Instant`의 처리 규칙을 구분했습니다.

해결(Solution): 서버는 시간대 환경변수와 `@JsonFormat`을 적용했습니다. 프론트엔드는 KST 원문을 그대로 검증하고 표시하는 공통 유틸을 만들고 Orval에서 `Instant` 필드를 별도로 처리했습니다.

결과(Result): 날짜 오차를 수정하고 AP 내역, 용어장, 약관, 홈에 같은 날짜 규칙을 적용했습니다. 원문 시각 유지와 잘못된 오프셋 차단은 회귀 테스트로 검증하도록 했습니다.

## 배포 결과

웹으로 배포했고 팀은 UMC INHA 10기에서 우수상(3등)을 받았습니다. 담당 화면은 Mock 데이터에서 실제 API 응답을 사용하도록 바꿨습니다.

제출 당일에는 모달, 탭, 카운트다운 상태를 필요한 범위로 옮겨 클릭 한 번에 페이지 전체가 다시 렌더링되던 문제를 줄였습니다.
