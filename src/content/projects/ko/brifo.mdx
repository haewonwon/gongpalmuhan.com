## 문제와 목적

BRIFO는 사용자가 투자 회사의 CEO가 되어 AI 사원에게 종목 분석을 맡기고, 보고서를 바탕으로 투자 방향을 결정하는 서비스입니다. 실제 매매 대신 결정과 회고를 반복하며 투자 판단을 연습하도록 만들었습니다.

개발 쪽 제약은 9주라는 기간과 계속 바뀌는 API였습니다. 명세가 바뀔 때마다 타입을 손으로 맞추면 빠뜨리기 쉬웠고, 서버 DTO를 화면에서 직접 쓰면 명세를 고칠 때 화면 코드까지 손봐야 했습니다.

## 주요 기술 결정

### Zod를 응답 검증 용도로 다시 제안

처음 회의에서는 입력 폼이 적다는 이유로 Zod를 쓰지 않기로 했습니다. 이후 API 연동을 준비하면서 Zod를 폼 검증이 아니라 **API 응답 검증** 용도로 다시 제안했습니다. TypeScript 타입은 컴파일할 때만 검사하므로, 실행 중 서버가 명세와 다른 데이터를 보내면 막을 수 없기 때문입니다. 팀원들이 직접 검토한 뒤 도입을 결정했습니다.

### Orval 생성 범위를 요청 함수, 타입, 스키마로 제한

Orval은 TanStack Query hook까지 생성할 수 있지만, 생성 범위를 요청 함수, DTO 타입, Zod 스키마로 좁혔습니다. Query Key와 캐시 정책을 생성 설정이 아닌 팀 코드에서 관리하기 위해서입니다. 대신 도메인 hook은 사람이 작성해야 하므로, 작성 순서와 "생성 파일은 수정하지 않는다" 같은 규칙을 `src/hooks/api/README.md`에 정리했습니다.

응답은 다음 순서로 처리합니다. Zod 검증과 Mapper를 `queryFn` 안에서 실행해, 서버 DTO가 아닌 화면 모델이 캐시에 저장됩니다.

```text
서버 응답
  → Axios 공통 인스턴스 (인증, refresh 처리)
  → Orval이 생성한 Zod 스키마로 검증
  → Mapper로 DTO를 화면 모델로 변환
  → TanStack Query 캐시
  → 화면 컴포넌트
```

이 규칙을 팀원들과 함께 적용해 40개 경로의 API를 연결했습니다.

## 문제 해결 사례

### 생성된 타입이 실제 응답과 다를 때

Orval로 만든 타입이 실제 응답과 맞지 않는 문제가 있었습니다. 원인을 추적해 보니 백엔드 Kotlin 응답 DTO 안에 `Item`이라는 같은 이름의 중첩 클래스가 여러 개 있었고, OpenAPI 스키마에서 이름이 충돌하고 있었습니다.

같은 구조를 쓰는 다른 목록 응답에도 같은 문제가 있을 수 있다는 점을 함께 백엔드에 전달했습니다. 서버에서 중첩 `Item` 13개를 모두 고유한 이름으로 바꿨고, 12개 도메인의 응답 DTO 21개가 수정됐습니다. 팀원이 이전에 증상만 보고했던 문제도 이때 함께 해결됐습니다.

### 운영 중 9시간 차이가 난 날짜

배포된 환경에서 일부 날짜가 9시간 어긋나 표시됐습니다. 증상에서 원인을 추적해 보니 서버의 JPA Auditing이 한국 시간(KST) 기준 Clock에 연결되지 않은 상태였습니다. 영향받는 영역과 확인 명령어, 필요한 환경변수를 정리해 전달했고, 어떤 필드를 KST `LocalDateTime`으로 직렬화하고 어떤 필드는 `Instant`로 둘지 응답 규칙을 정했습니다.

프론트엔드에서는 [#102](https://github.com/Team-BRIFO/BRIFO-front/pull/102)에서 다음을 반영했습니다.

- KST `LocalDateTime` 응답을 원문 그대로 검증하고 표시하는 유틸과 회귀 테스트
- Orval 설정에서 `Instant` 필드를 구분하는 전처리 ([`orval.config.ts`](https://github.com/Team-BRIFO/BRIFO-front/blob/dev/orval.config.ts))

서버 쪽에서는 환경변수와 `@JsonFormat` 적용으로 수정됐습니다. 함께 제안했던 `dateTimeProviderRef` 연결은 반영되지 않았습니다.

## 결과와 한계

- 웹으로 배포했고, 팀은 UMC INHA 10기에서 우수상(3등)을 받았습니다.
- 담당 화면을 목 데이터에서 실제 API로 전환했고, API 연동 규칙을 팀원들과 40개 경로에 적용했습니다.
- 제출 당일 모달, 탭, 카운트다운 상태를 필요한 범위로 옮겨 클릭 한 번에 페이지 전체가 다시 렌더링되던 문제를 줄였지만, 렌더링 횟수나 응답 시간을 전후로 측정하지는 않았습니다.
