## 프로젝트 소개

Unplan은 그날의 컨디션과 생활 패턴에 맞춰 할 일을 조정하는 스케줄러 앱입니다. React Native와 Expo로 만들었습니다.

## 주요 구현

디자인 토큰과 Typography, Tag 등 공통 UI를 만들었습니다. 로그인과 온보딩, 일정 화면도 구현했습니다.

카카오 로그인과 Google Sign-In을 연동하고 인증 토큰을 `expo-secure-store`에 저장했습니다. 카카오톡이 설치되어 있지 않으면 카카오 계정 로그인으로 전환하도록 처리했습니다. 백엔드가 직접 소셜 로그인과 토큰 교환을 검증할 수 있도록 별도의 웹 도구도 만들었습니다.

Orval로 OpenAPI 명세에 맞는 요청 함수와 타입을 생성하고 Axios로 API를 호출하도록 구성했습니다. 서버 데이터는 직접 작성한 TanStack Query hook으로 관리하고 세션 같은 앱 상태는 Zustand에 두었습니다.

## 문제 해결

### 미리보기 배포 51회 중 46회를 EAS Update로 처리

문제 정의(Problem): 네이티브 SDK가 포함된 앱이라 JavaScript만 바꿔도 전체 빌드를 기다려야 했습니다.

접근 과정(Process): 네이티브 코드와 설정, 의존성 변경 여부를 기준으로 Preview Build가 필요한 경우와 JavaScript 번들만 배포할 수 있는 경우를 나눴습니다.

해결(Solution): GitHub Actions가 `develop`의 변경 경로를 검사해 네이티브 관련 파일이 바뀌면 EAS Build를, 그 외에는 EAS Update를 실행하도록 구성했습니다. 필요하면 수동으로 네이티브 빌드를 강제하는 옵션도 뒀습니다.

결과(Result): 성공한 미리보기 배포 51회 중 46회를 EAS Update로 처리했습니다. 배포 작업 평균은 iOS 빌드 약 7분, EAS Update 약 2분이었습니다.

### 앱 복귀 후 서버 데이터 갱신 문제 수정

문제 정의(Problem): 컨디션과 수면 기록 화면에 다시 들어오거나 앱에 복귀해도 지난 기록이 갱신되지 않았습니다.

접근 과정(Process): 앱 활성화 감지와 캐시 설정을 확인했습니다. React Native에는 브라우저의 포커스 이벤트가 없고 지난 기록의 `staleTime`은 `Infinity`, 전역 기본값은 5분으로 설정되어 있었습니다.

해결(Solution): `AppState` 변경을 TanStack Query의 `focusManager`에 연결하고 전역 기본값과 지난 기록의 `staleTime`을 0으로 바꿨습니다. 오늘 기록은 기존대로 기록 mutation 후 캐시를 무효화해 갱신했습니다.

결과(Result): 앱 복귀와 화면 재진입 시 지난 기록을 다시 요청하도록 바꿨습니다. 요청 수 변화는 따로 측정하지 않았습니다.

## 배포 결과

TestFlight로 배포했고 팀은 TAVE 17기에서 우수상(2등)을 받았습니다. 현재 TestFlight 빌드는 내려가 있습니다.

초기에는 Android 미리보기 빌드도 구성했고 현재는 iOS 미리보기와 TestFlight 릴리스 중심으로 전환했습니다.
