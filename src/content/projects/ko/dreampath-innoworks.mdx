## 프로젝트 소개

DreamPath와 InnoLAB은 사용자가 AI와 대화하며 결과를 시각화하는 웹 서비스입니다. 주식회사 프랜더에서 인턴으로 일하며 Django에 묶여 있던 화면을 React로 옮기고 다국어 UI를 적용했습니다.

## 주요 구현

로그인 상태와 진행도, 주차 상태 등 서버 데이터를 React 화면에 연결했습니다. AI 응답은 서비스 화면 안에서 HTML로 렌더링했습니다.

두 서비스 모두 차시별 채팅 페이지 클래스와 스트리밍 함수를 각각 9개에서 `stage`를 받는 공통 구현 1개로 통합했습니다. URL 패턴은 18개에서 2개로 줄이고 SSE 응답 생성도 9곳에서 1곳으로 모았습니다.

대화 모델 9개도 `stage` 필드가 있는 모델 1개로 통합했습니다. 로컬 SQLite ORM 실험에서 같은 대화 180개를 읽는 전체 9차시 조회가 9쿼리에서 1쿼리로 줄었고 반환 내용도 같았습니다. 단일 차시 조회는 느려진 경우가 있어 검색 범위와 인덱스 점검을 후속 과제로 남겼습니다.

영어, 일본어, 중국어, 스페인어 언어 리소스를 구성해 화면에 적용했습니다. GitHub Actions로 배포도 자동화했습니다.

## 문제 해결

### React 전환으로 로그인 화면 이동 시 HTML 재요청 제거

문제 정의(Problem): Django 템플릿 구조에서는 대시보드에서 로그인 화면으로 이동할 때 새 HTML 문서를 요청했습니다.

접근 과정(Process): 초기 로딩과 내부 화면 이동을 나눠 확인했습니다. Chromium에서 CPU 속도를 4배 늦추고 네트워크를 10Mbps, 지연을 40ms로 설정해 게스트 화면을 각 7회 측정했습니다.

해결(Solution): 화면과 라우팅을 React로 옮겼습니다. React Router가 이미 내려받은 앱 안에서 로그인 화면을 표시하도록 했습니다.

결과(Result): 두 서비스 모두 새 HTML 요청이 1회에서 0회로 줄었습니다. 클릭부터 입력란 표시 후 두 프레임까지의 중앙값은 DreamPath 183.60ms에서 66.40ms, InnoLAB 133.50ms에서 72.80ms로 줄었습니다. 첫 콘텐츠 표시는 두 서비스 모두 늦어져 초기 로딩과 내부 이동의 효과를 따로 봤습니다.

### DreamPath 학생 조회 범위를 학급 단위로 제한

문제 정의(Problem): 학생 목록에서 최신 이미지를 찾을 때 학급 조건 없이 사용자 이름과 차시로 검색했습니다. 다른 학급의 대화가 늘어날수록 조회 비용도 커졌습니다.

접근 과정(Process): 학급은 30명으로 고정하고 전체 대화량을 5,580건과 54,180건으로 나눴습니다. 기존 SSR 요청과 현재 API의 처리 시간과 쿼리 수를 비교했습니다.

해결(Solution): 학생 조회에 학급 FK 조건을 넣어 검색 범위를 좁히고 기존 FK 인덱스를 사용할 수 있도록 했습니다.

결과(Result): SQLite에서 전체 대화 54,180건을 둔 40회 조회 중앙값이 1,369.86ms에서 72.80ms로 94.7% 줄었습니다. 5,580건 조건에서는 쿼리가 95개에서 63개로 줄었습니다. SSR HTML과 API의 최종 구현을 비교한 값으로 학생별 반복 조회는 남아 있습니다.

### InnoLAB 이미지 생성을 대화 저장 트랜잭션에서 분리

문제 정의(Problem): 대화 저장 트랜잭션 안에서 이미지를 생성해 기다리는 동안 같은 학생 행의 다른 쓰기도 막혔습니다. 이미지 결과를 DB에 저장하다 실패하면 대화와 차감 기록까지 롤백됐습니다.

접근 과정(Process): 과거 커밋을 MySQL에서 실행해 이미지 함수에 고정 지연을 넣고 별도 연결로 같은 학생 행을 수정했습니다. 외부 함수와 결과물 DB 저장에 각각 오류를 넣어 대화가 보존되는지도 확인했습니다.

해결(Solution): 대화와 차감 기록을 먼저 커밋한 뒤 이미지를 생성하고 결과를 저장하도록 트랜잭션을 나눴습니다.

결과(Result): 외부 지연 500ms를 넣은 25회 실험에서 트랜잭션 점유 중앙값은 508.85ms에서 1.57ms로 99.7% 줄었습니다. 같은 학생 행의 UPDATE 완료 시간도 505.89ms에서 0.52ms로 줄었습니다. 이미지 결과 저장에 DB 오류를 넣은 20회 실험에서는 대화 보존이 0회에서 20회로 바뀌었습니다. 전체 채팅 요청은 여전히 이미지 생성을 기다려 약 0.5초가 걸렸습니다.

### DreamPath 프롬프트의 현재 답변 중복 제거와 입력 축소

문제 정의(Problem): 현재 답변을 DB에 저장한 뒤 이력과 현재 답변을 요청에 함께 넣어 같은 답변이 두 번 전달됐습니다. 누적 지시와 질문 파싱도 요청 구성을 복잡하게 만들었습니다.

접근 과정(Process): 9개 차시와 5개 언어, 이력 길이 4종류를 조합한 합성 입력 180개를 실제 채팅 뷰에 넣었습니다. AI 호출 직전 메시지의 본문 토큰을 같은 토크나이저로 계산하고 현재 답변의 등장 횟수를 확인했습니다.

해결(Solution): 과거 이력에서 현재 턴을 제외하고 현재 턴 중심으로 프롬프트를 구성했습니다. 질문 목록과 출력 형식도 보완했습니다.

결과(Result): 1회 요청 기준 본문 토큰 평균이 1,904.46에서 694.01로 63.6% 줄었고 합성 입력 180개 모두 현재 답변이 2회에서 1회로 줄었습니다. 외부 모델 호출 없이 입력 구성을 비교한 값으로 실제 청구 비용과 응답 품질은 측정하지 않았습니다.

## 배포 결과

두 서비스 모두 영어, 일본어, 중국어, 스페인어 UI로 운영 중입니다. 회사 프로젝트라 코드 링크는 공개하지 않습니다.
